# Migrations — Rooster One

Histórico incremental de `prisma/migrations/` (25 migrations), cada qual em uma pasta
`<timestamp>_<descricao>/migration.sql`. O provider registrado em `migration_lock.toml` é `postgresql`: todas as
migrations foram escritas e aplicadas sobre PostgreSQL.

## Comandos do projeto (`package.json`)

| Script npm | Comando | Uso |
|---|---|---|
| `npm run prisma:migrate` | `prisma migrate dev` | Desenvolvimento: cria e aplica nova migration a partir da diferença em relação ao `schema.prisma` e gera o cliente. |
| `npm run prisma:deploy` | `prisma migrate deploy` | Produção e integração contínua: aplica as migrations pendentes existentes em `prisma/migrations/`, sem gerar novas e sem confirmação interativa. |
| `npm run prisma:generate` | `prisma generate` | Gera o Prisma Client a partir do `schema.prisma` (PostgreSQL). |
| `npm run db:seed:dev` | `ts-node prisma/seed-dev.ts` | Popula banco de desenvolvimento com dados de demonstração (ver `06-seeds.md`). |
| `npm run prisma:generate:test` | `prisma generate --schema ./prisma/schema.test.prisma` | Gera o cliente de teste (SQLite), utilizado por `test:e2e`. |
| `npm run prisma:db:push:test` | `prisma db push --schema ./prisma/schema.test.prisma` | Sincroniza o schema de teste diretamente no SQLite, sem gerar arquivos de migration (utilizado apenas nos testes e2e). |

## Observação histórica

O schema atual **não possui** o modelo Perfil/Role, mas o banco já o possuiu. As migrations 1, 4 e 10 registram a
evolução completa: o modelo original (`usuario → perfil → permissao`, com as tabelas `perfis`, `usuarios_perfis` e
`perfis_permissoes`) foi introduzido na primeira migration e desmontado na migration 10
(`20260916125542_usuarios_permissoes`), com migração dos dados para o vínculo direto atual (`UsuarioPermissao`). A
informação é relevante para quem consulta apenas o `schema.prisma` vigente, que reflete o estado final; o histórico
de migrations preserva a motivação da mudança nos comentários do próprio SQL.
