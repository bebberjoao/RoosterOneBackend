LoginPOST /auth/login
access token (JWT) — 8 horas refresh token aleatório — 30 dias
  • Uma sessão é gravada com o hash SHA-256 do refresh token (o token em si não é armazenado).
Usocada requisição
  • Cabeçalho Authorization: Bearer <access token>, anexado pelo cliente HTTP do frontend.
  • O usuário é consultado no banco a cada requisição: usuário desativado perde o acesso de imediato.
RenovaçãoPOST /auth/refresh
  • Access token expirado: a API responde 401, e o frontend renova a sessão uma única vez (chamadas simultâneas aguardam a mesma renovação) e repete a chamada.
  • Emite novo par de tokens e revoga a sessão utilizada (rotação); usuário inativo não renova.
  • Falha de rede durante a renovação não encerra a sessão.
Encerramentorevogação
  • Logout (POST /auth/logout): revoga a sessão atual.
  • Troca de senha (por recuperação ou pelo administrador) e desativação do usuário: revogam todas as sessões abertas.
Por que a rotação: cada refresh token vale uma única vez. Se um terceiro o utilizar, a renovação seguinte do usuário legítimo falha e exige novo login: o uso indevido se manifesta, em vez de passar despercebido.
